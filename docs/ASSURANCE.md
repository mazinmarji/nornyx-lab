# Honest assurance statement

## Strongest supported platform statement

Nornyx Academy is an interactive training platform whose default business effects are inert. For
the named cooperative in-process enforcement surfaces exercised by a scenario, the academy can
show a released Nornyx decision, whether the wrapped inert callable was entered and completed,
the evidence events supplied by the academy/adapter, validation findings, and the exact version/
revision bindings represented in those events.

For the default Atlas demonstration, the captured untrusted-page plan reaches inert publication
in the ungoverned path (`1 attempt / 1 completion`). On the named governed wrapper, a missing
approval prevents entry (`0 / 0`) and the released Nornyx Authorizer returns
`CROSSING_APPROVAL_REQUIRED`. This supports a Tier 2 cooperative claim about that named path and
run. It does not support “the agent,” “CrewAI,” “LangGraph,” “the application,” or “all publishing”
being governed.

## Claim model

Every material lesson asks five questions:

1. **Target:** which exact planner, graph node, tool, resource, artifact, or workflow is named?
2. **Surface:** which callable, adapter hook, gate, or external boundary is observed/enforced?
3. **Mechanism:** what declaration, decision, validation, or enforcement behavior occurred?
4. **Evidence producer:** which component emitted each occurrence and counter?
5. **Adversary and limitation:** which bypass, unobserved path, or unverifiable fact remains?

Claims are returned as supported, unsupported, or indeterminate. “Unknown” is not rendered as
zero and missing evidence is not converted into prevention.

## Nornyx scope

Nornyx declares, checks, composes, generates, locks, decides, and validates supplied evidence.
It is not an LLM, planner, orchestrator, agent framework, workflow engine, tool runtime, transport,
identity provider, human-authentication service, unavoidable PEP, or independent attestor. It does
not govern this academy merely because the academy uses Nornyx.

## Approval statement

A generic capability request has no approval field. Validating an approval request does not
mutate the Authorizer. The demonstrated combined approval path is a gated zone-crossing request
carrying a bound assertion. The assertion model validates declared attributes; authentication of
the person or system that produced it remains outside the lab boundary.

## Adapter statement

- CrewAI 1.15.4: cooperative synchronous `BaseTool._run` through native kickoff only.
- LangGraph 1.2.2: cooperative synchronous `StateGraph` node with declared occurrence metadata.

Async/distributed internals, arbitrary delegation, handoffs, subgraphs, tool-node internals, and
alternate call paths are not implicitly covered. Adapter conformance is scoped inventory and
behavioral evidence, not a Tier 3 boundary.

## Platform-versus-target distinction

The product demonstrates governance of inert targets inside the academy. The academy’s API,
database, web process, host, and operator are protected by ordinary application/container
controls documented in [SECURITY.md](SECURITY.md), not by a claim that its training contracts
govern the platform itself.

## Residual risks

- a cooperative wrapper can be bypassed by an unwrapped path;
- application evidence can omit or misstate real-world events;
- a live model can propose a different plan;
- framework behavior outside pinned, tested versions may change;
- local single-user storage has no authentication or independent identity proof;
- an authenticated human approval system is not implemented;
- the training container is not a hostile-code sandbox or external PEP;
- no standards certification is implied by an educational mapping.

Any future stronger claim requires a stronger, independently enforced and unavoidable architecture,
independent observation, a declared adversary model, and tests that exercise that exact boundary.
